APPLICATION UML

How each state's views connect to models, services and shared resources.

Application ownership

The game composes the application. State entry selects the visible Flame World. Campaign/settings survive world changes; combat is replaced on level loading. Pause retains the current arena and combat. Asset services last for the game instance. The game owns LevelCacheService, which manages fighter/scenario caches.

Menu

Menu contains Intro, Logo, Main and Lore substates. Intro/Logo use the same view class with a different frame index. MainMenuView receives callbacks, a loading error value and settings controls; it has no dedicated MainMenuModel. Settings controls reach shared settings and their cache through the game.

Loading

LoadingView gets a description string and LoadingCacheService. The game reads the campaign's current LevelDefinition, creates combat and mounts the next arena off-camera before entering Level. LoadingView does not construct those models.

Arena / Level

ArenaView holds combat and shared caches. Each entity references the exact model updated by combat. Its handler selects frames from state/time. ArenaHud and LevelResultPopup are camera viewport children, not ArenaView children; both hold the game and read the relevant state through it. Animations cannot change rules.

Pause

PauseView receives callbacks and SettingsControls. It does not contain combat or copy fighter models. KuradiSaased retains the existing ArenaView and simulation, stops combat updates, and restores that same world on resume.

Score

CampaignModel records one LevelResult per encounter. GameScoreView holds that result and scalar snapshots for totals, level numbers and next-level status. It does not hold CampaignModel directly. Continue calls the game, which advances the campaign and selects Loading or End. The old arena reference is cleared.

End

GameEndView receives completion and score snapshots plus a menu callback. There is no EndModel and no direct CampaignModel field. The campaign remains owned by the game; a new run resets it when the player starts from Menu.

UML notation: diamond = owns lifecycle · hollow triangle = inherits · solid arrow = held reference · dashed arrow = uses or receives values through the game.
Score and End receive snapshots; Pause retains the arena through the game. They do not each own a copy of the gameplay models.
